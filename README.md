# Граф знань MovieLens у Neo4j

Граф на повному MovieLens 1M містить 6 040 користувачів, 3 883 фільми, 18 жанрів, 1 000 209 оцінок та 6 408 зв’язків фільм–жанр. Джерело даних — [MovieLens 1M, GroupLens](https://grouplens.org/datasets/movielens/1m/).

## 1. Схема

```text
(:User {userId, gender, age, occupation})
   └── [:RATED {rating, timestamp}] ──► (:Movie {movieId, title, year})
                                           └── [:HAS_GENRE] ──► (:Genre {name})
```

Користувач, фільм і жанр мають власну ідентичність. Числові ідентифікатори прийшли з MovieLens. `age` та `occupation` — коди категорій джерела, `rating` — ціле від 1 до 5, `timestamp` — Unix-час у секундах. Рік виділено із суфікса назви, а поштові індекси опущено, бо запити їх не використовують.

Оцінку записано як ребро з властивостями, оскільки в цьому наборі одна пара користувач–фільм має максимум одну оцінку. Це дозволяє за один перехід обійти оцінку й одразу застосувати поріг. Окремий вузол `Rating` виправдав би додаткові переходи за наявності кількох подій для однієї пари, джерел оцінок або самостійних зв’язків на кшталт перевірок і коментарів.

Жанр як вузол з унікальною назвою дозволяє як перевіряти жанри фільму, так і переходити від жанру до всіх пов’язаних фільмів. Він також дає місце для синонімів і зв’язків між жанрами. Список був би компактнішим для читання однієї картки. Для Q1 і Q4 потрібне групування та навігація від жанру, тож спільний вузол зручніший. Ціна такого рішення — популярний жанр може мати великий ступінь.

## 2. Підготовка даних та імпорт

Потрібні Python 3.10+ і локальний Neo4j 5.26 з APOC; для частини 5 також потрібен GDS. [Архів MovieLens](https://files.grouplens.org/datasets/movielens/ml-1m.zip) розпакуйте у `data/`, щоб файли `movies.dat`, `ratings.dat` та `users.dat` опинилися в `data/ml-1m/`. Дані завантажуються зі сторінки GroupLens згідно з її умовами.

```bash
python3 convert.py
cp .env.example .env
# Заповніть NEO4J_PASSWORD у локальному .env перед запуском.
docker compose up -d
docker compose logs neo4j
```

Дочекайтеся готовності Neo4j і відкрийте [Neo4j Browser](http://localhost:7474/browser/). Логін за замовчуванням `neo4j`. Імпорт запускається з кореня проєкту:

```bash
docker compose exec -T neo4j sh -c '
  export NEO4J_USERNAME=neo4j NEO4J_PASSWORD="${NEO4J_AUTH#*/}"
  exec cypher-shell -d neo4j
' < queries/part2_load.cypher
```

[Конвертер](convert.py) читає Latin-1 із роздільником `::`, перевіряє ключі, діапазон оцінок і наявність обох кінців ребер, а потім записує UTF-8 CSV у `import/`. [Cypher імпорту](queries/part2_load.cypher) спочатку створює три обмеження унікальності з індексами для `User.userId`, `Movie.movieId`, `Genre.name` і очікує їх готовності. Далі `MERGE` користувачів та фільмів за ключем оновлює їхні властивості. Третій прохід розбиває список жанрів, нормалізує пробіли і додає унікальні жанри та `HAS_GENRE`. Останній прохід знаходить кінцеві вузли через готові індекси й додає `RATED` пакетами по 5 000 рядків через `apoc.periodic.iterate`. Послідовний запис зменшує конкуренцію за блокування на популярних фільмах.

Критерії перевірки після імпорту — нульові `failedOperations` і `failedBatches`, 201 пакет, 1 000 209 зафіксованих оцінок, кількості з першого абзацу й усі три індекси `ONLINE`. Перший запуск та повторний імпорт перевірено на локальних Neo4j Community 5.26.33 та APOC 5.26.33. Повтор обробив усі оцінки з `relationshipsCreated = 0`. Конфігурація Docker Compose пройшла перевірку CLI, фактичний імпорт виконувався в нативному Neo4j.

## 4. Супервузли і вимірювання

`Drama` має 1 603 фільми. Серед фільмів для контрольного досліду взято `American Beauty` (#2858, ступінь 3 430) та `Kull the Conqueror` (#1606, ступінь 111). Для інтерактивного фільтра «драма, конкретний рік» можна додати range-індекс `Movie.year`, почати з вибіркового року і перевіряти `HAS_GENRE` для кандидатів. Для панелі з кількістю високих оцінок дешевше читати заздалегідь підтримуваний лічильник на фільмі. У рекомендаціях відсікаємо слабких сусідів і обмежуємо вибірку до другого обходу; завеликий поріг може погіршити повноту для рідкісних фільмів. Кешований лічильник або вибірку слід звіряти з оцінками після змін.

## 5. Додатково — Graph Data Science

[Cypher](queries/part5_gds.cypher) створює дві зважені неорієнтовані проєкції в пам’яті. Вага — число спільних фільмів або глядачів з оцінками ≥4. Для обмеження вартості обрано 300 найбільш оцінених фільмів серед тих, що мають понад 20 оцінок, і кожного 15-го з 6 040 користувачів за `userId` (402). Збережено до 15 000 найсильніших неорієнтованих ребер у кожній проєкції з детермінованим порядком при рівності. Окремі запити знімають версії й розміри проєкцій, запускають алгоритми та видаляють проєкції після обчислень. [Фактичні результати GDS 2.13.4](results/part5_gds.json).

- **PageRank.** Зважений PageRank виділяє фільми, які часто високо оцінювали разом з іншими центральними фільмами. `Star Wars IV` має 4.09683 на 2 991 оцінці, `Star Wars V` — 4.08846, `American Beauty` — 3.75073 на 3 428 оцінках. Відмінність від сортування за кількістю оцінок показує залежність від структури зв’язків.
- **Louvain.** Отримано 83 спільноти, з них три мають 137, 110 і 75 учасників, решта 80 — по одному. Modularity 0.07664 свідчить про слабке відокремлення. Жанри зіставлено за кількістю позитивних оцінок учасників спільноти. Топи трьох найбільших — Drama/Comedy/Romance, Action/Comedy/Drama і Drama/Comedy/Action, тому називати їх чіткими клубами за одним жанром підстав мало. Повні розміри й жанри, зокрема десять найбільших груп, у JSON.

Ще десять пар без маршруту в цій проєкції. Якщо вартість дорівнює оберненій силі зв’язку, середнє число переходів оптимальних маршрутів зростає до 2.2143. Для висновку про «шість рукостискань» у всьому MovieLens потрібна репрезентативніша проєкція з вимірюванням недосяжних пар.

## 6. Граф і SQL

Навігацію Q6 легше описати через `shortestPath` над типом ребра. У SQL можна реалізувати пошаровий обхід через рекурсивний CTE. У прикладі таблиця `ratings(user_id, movie_id, rating)` має унікальну пару `(user_id, movie_id)` та індекс `(movie_id, user_id)`. Кожна ітерація додає два ребра й проходить від одного користувача через фільм до іншого. `UNION` прибирає повтори `(user_id, hops)`, мінімум визначає найкоротшу довжину в межах чотирьох ребер. Для повернення всього маршруту SQL додатково зберігав би послідовність вузлів і контролював повтори на шляху.

```sql
WITH RECURSIVE reachable(user_id, hops) AS (
    VALUES (1, 0)
    UNION
    SELECT peer.user_id, reachable.hops + 2
    FROM reachable
    JOIN ratings AS own ON own.user_id = reachable.user_id
    JOIN ratings AS peer ON peer.movie_id = own.movie_id
    WHERE reachable.hops < 4
      AND peer.user_id <> reachable.user_id
)
SELECT MIN(hops) AS distance
FROM reachable
WHERE user_id = 46;
```

Запит виконано в SQLite на 1 000 209 оцінках. Результат — `distance = 4`, як у Cypher.

Для щомісячної статистики оцінок, зрізів за жанром і демографією або вивантажень краще підходить реляційна таблиця фактів `ratings` з індексом часу, таблицями `movies` і `users` та таблицею зв’язків жанрів. Вона дозволяє явно визначити зерно рядка й обчислити агрегати на одному скануванні або читати матеріалізовані підсумки. Для Q4 треба свідомо повторити оцінку в кожному жанрі багатожанрового фільму. Це правило так само діє в реляційному звіті.

Для Q1 можна матеріалізувати `ratingSum` і `ratingCount` на `Movie` і розраховувати середнє до обходу окремих оцінок. Для Q5 популярні рекомендації можна прискорити матеріалізованим зваженим `SIMILAR` між користувачами, з датою зрізу та обмеженням найближчих сусідів. Обидві зміни переводять частину роботи з читання в оновлення. Для Q1 потрібні атомарні корекції при редагуванні оцінки. Для Q5 потрібно фіксувати свіжість, перебудовувати схожість після змін і мати поведінку для нових або малоактивних користувачів.
